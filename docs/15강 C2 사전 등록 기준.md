# 15강 C2 사전 등록 기준 — 부탁하지 않은·중복 약속 생성

> 개선 전(before) 실험을 돌리기 **전에** 커밋한다. 결과를 본 뒤 이 기준을 바꾸지 않는다.

## 문제
도구 선택기가 사용자가 부탁하지 않았는데 `create_reminder` 를 고르거나, 확인·조회 질문에 같은 약속을 다시 만든다.
staging 기준 버전 `5c5f2de` + 로컬 실사용에서 약속 도구를 쓴 16턴 중 6턴(38%).
처음 어긋난 단계: `choose-tools`. 지시문에 이미 "분명히 부탁할 때만" 규칙이 있는데도 지키지 않는다.

## 데이터셋 `data/eval/reminder_intent.jsonl` (23개)
| 종류 | 개수 | 출처 | 통과 조건 |
|---|---|---|---|
| 문제 항목 `must_not_create` | 12 | 트레이스 7 + 새 문장 5 | 고른 도구에 `create_reminder`, `cancel_reminder` 가 없다 |
| 정상 항목 `must_create` | 11 | 트레이스 5 + 새 문장 6 | 고른 도구에 `create_reminder` 가 있다 |

- 통과 조건 예: P01 "다음주 금요일에 면접 있어 좀 떨려" → 약속 도구 없음이면 통과. N08 "내일 7시에 깨워줘" → `create_reminder` 가 있으면 통과.
- 날짜·시각이 맞는지는 C1(날짜 해석) 범위라 채점하지 않는다.
- 회귀 확인: 기존 `data/eval/tool_selection.jsonl` 41개를 같은 `choose()` 로 돌려 도구 정답 수를 센다.

## 실행 방법
- `python scripts/eval_reminder.py --label <이름> --runs 3 --regression`
- 모델: staging 과 같은 gpt-4o-mini, 온도 기본값. 조건마다 **3회** 반복.
- 한 번에 한 가지만 바꾼다.

## 내보낼 기준 (세 가지 모두 만족해야 배포)
1. **문제 항목 통과율**: 3회 평균 **90% 이상**, 그리고 3회 중 최저 **80% 이상**
2. **정상 항목 통과율**: 3회 평균 **90% 이상**, 그리고 개선 전 평균보다 **5%p 넘게 떨어지지 않음**
3. **기존 도구 평가(41개)**: 3회 평균 정답 수가 개선 전 평균보다 **2개 넘게 떨어지지 않음**

하나라도 못 넘으면 배포하지 않고, 실패한 시도로 기록한 뒤 다른 한 가지를 바꿔 다시 잰다.

## 예상(가설, 채점에 쓰지 않음)
- 개선 전: 문제 항목 50~70%, 정상 항목 85~100%
- 가장 어려운 정상 항목: N04 "모레 점심에 택배 찾는 것도"(부탁 말 없이 앞 문맥에 이어짐)
