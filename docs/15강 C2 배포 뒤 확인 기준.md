# 15강 C2 배포 뒤 확인 기준 (5단계)

> 새 대화를 보내기 **전에** 커밋한다. 결과를 본 뒤 바꾸지 않는다.

## 무엇을 보내나
- `data/eval/verify_c2_conversations.json`: 15세션 48턴. **데이터셋(`reminder_intent.jsonl`)과 같은 문장 없음**, 표현을 바꾼 새 대화
  - `must_not_create` 24턴(일정 이야기, 확인·조회 질문) / `must_create` 14턴(부탁) / 채점 제외 10턴(`-` 9, `ambiguous` 1)
  - 일부러 안전장치 규칙에 없는 표현도 넣었다: "꼭 기억시켜 줘", "알림 맞춰 둘래?", "까먹을 것 같아"(애매, 채점 제외)
- 같은 대화를 두 버전에 보낸다. Cloud Run 리비전 태그로 주소를 나눈다(트래픽 배분은 그대로 100% 최신).
  - `before` = `5c5f2de`(리비전 00019) / `after` = `44bdaf2`(리비전 00020)
- 방문자 모드, 버전마다 새 방문자 ID(기억이 섞이지 않음)

## 어떻게 세나 (`scripts/verify_c2.py`)
- Langfuse 트레이스를 **version 으로 나누고**, 트레이스 안에서 **실제로 실행된 도구(tool:\*)** 로 판정한다
- 같은 현상 = `must_not_create` 턴에서 `create_reminder` 또는 `cancel_reminder` 실행
- 정상 = `must_create` 턴에서 `create_reminder` 실행

## 판정 기준
1. **문제가 줄었다**: after 의 같은 현상 횟수 < before 횟수, 그리고 after 비율 ≤ 10%(24턴 중 2턴 이하)
2. **정상 요청을 잃지 않았다**: after 의 정상 생성 수 ≥ before − 1 (14턴 기준)
3. 지연·비용은 기준 없이 버전별 중앙값·p90·합계를 기록한다(안전장치는 모델 호출을 늘리지 않으므로 차이가 없을 것으로 예상)

1·2를 모두 만족하면 "배포 뒤에도 문제가 줄었다", 아니면 결과와 이유를 그대로 REPORT.md 에 적는다.
한 번 실행이라 흔들림이 있다. before 는 이미 4단계에서 3회 반복으로 흔들림을 봤으므로 여기서는 1회씩 보낸다.
